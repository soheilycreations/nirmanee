# Codebase audit — Nirmanee website

_Audited: 2026-11-08 · Commit `b2cf01d` (main) · Auditor: lead engineer (foundation task)_

## 1. Summary

The current site is a **static visual prototype**. Every product, price, rating, review, order and
dashboard number is hardcoded in page files. Supabase is installed but **never queried**. No cart,
no checkout, no auth, no uploads, no payments, no i18n. Nothing saves anywhere: the "Add to Order",
"Subscribe", "Submit review" and POS "Checkout" buttons do nothing.

What has value: the brand assets (logo, real product photos), the list of 12 services, the
product-detail layout ideas (variant pickers, upload zone) and the general Tailwind setup.
Everything else should be rebuilt against the new schema (`docs/SCHEMA.md`).

Stack versions: Next.js 16.1.6 (App Router, Turbopack), React 19.2.3, Tailwind CSS 4 (CSS-first
config, no `tailwind.config.*`), TypeScript 5 (`strict: true`), `@supabase/supabase-js` 2.99,
`lucide-react`, `clsx`, `tailwind-merge`. `npm run build` passes; `eslint src` reports
**14 errors, 22 warnings**.

## 5. Data & existing schema

- **All UI data is hardcoded.** `src/lib/supabase.ts` is never imported.
- `supabase/schema.sql` (not a migration) defines `products` (`type standard|sqft`), `orders`
  (`new|processing|completed`), `order_items` (`file_url`). No users/profiles, staff roles, jobs,
  proofs, messages, payments, carts, categories table, options or i18n columns.
- Unknown whether this legacy schema was ever applied to the live Supabase project — **needs
  confirmation** (see Decisions). The new migration assumes a fresh project.

## 6. Security issues

1. Public `/admin` + `/admin/pos`, linked from every page (finding 1).
2. Legacy RLS: any authenticated user = admin (finding 2).
3. No server-side price computation exists yet — when building checkout, prices must never come
   from the client (the POS computes prices in the browser).
4. Uploads are not implemented; when they are, files must go to a **private** R2 bucket via
   short-lived presigned URLs with server-side size/type checks (500 MB cap), never `public/`.
5. `src/lib/supabase.ts` silently falls back to placeholder credentials — misconfiguration would
   go unnoticed; replace with fail-fast env validation (zod).
6. **No secrets found** in the repo or in git history (checked for Supabase URLs/JWTs, `sk_`,
   merchant secrets). Only `NEXT_PUBLIC_SUPABASE_URL/ANON_KEY` are referenced, which are public
   by design.
7. No security headers / CSP configured in `next.config.ts`.

## 7. SEO issues

1. Default title/description (fixed at root level in this branch).
2. No per-page `generateMetadata`; client-only product page cannot export metadata.
3. No `sitemap.xml`, `robots.txt`, canonical URLs, Open Graph images, JSON-LD
   (`LocalBusiness`/`Product`/`BreadcrumbList`).
4. Numeric product URLs (`/product/1`) instead of slugs; unknown ids return product 1 with 200.
5. Image filenames `WhatsApp Image …jpeg` with spaces; alt texts guessed and some don't match the
   image; no `next/image`.
6. Fake review counts/ratings — would violate Google review-snippet policies if marked up.
7. Dead internal links (footer, header) waste crawl budget and hurt UX.
8. `lang="en"` only; Sinhala tagline embedded in English page without `lang="si"`; no
   `hreflang` alternates. (next-intl with `/en` + `/si` routes planned in P1.)
9. NAP (name/address/phone) incomplete: no street address or map for Kalutara local SEO.
